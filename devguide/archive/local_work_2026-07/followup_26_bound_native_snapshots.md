Recovered on **2026-10-08** in the existing editable Python 3.14.7 environment.

## Recovered utility

Four explicit clients cover five existing native pathways, using unchanged public
inputs rather than new source acquisitions:

| Pathway | Native input | Qualified standalone assertions |
|---|---|---|
| AlphaFill metadata | `alphafill/metadata__P60174.json` | 1 model / 86 transplants |
| GlyGen protein detail | `glygen/protein__P60174.json` | 3 glycosylation / 13 phosphorylation |
| SIFTS mappings | `sifts/mappings__1hti.json` | 2 source-declared segments |
| LIGYSIS result page | `ligysis/result__P60174__1.html` | 2 sites / 20 displayed rows / 4 directed correspondence tables |
| LIGYSIS structure mapping | `ligysis/mapping__P60174__1__7t0q.json` | 14 directed mapping / identity / remapping tables |

`SnapshotAlphaFillClient`, `SnapshotGlyGenClient`, `SnapshotSIFTSClient` and
`SnapshotLigysisClient` accept a path, explicit source metadata and optional SHA.
A private shared helper validates/detaches constructor arguments and checks exact
source/kind/normalized-query/unknown-revision binding before file access. Native
format is fixed by the reader. Original-byte SHA is checked before gzip decoding,
then the existing native validator qualifies content. Missing files are unavailable;
foreign context, duplicate keys, invalid bytes, wrong native identity or shape are
failures, never biological absence. Standalone maps preserve their original receipt.

Source metadata is caller declared. Original retrieval time remains unknown when
not supplied; local read time is separate. Native scientific revisions remain
unknown and are not replaced by software/API/run versions. Declared terms do not
change registry rights. No source request, linked fetch, job, automatic card
admission/enricher, schema change, guessed chain identity or canonical projection.
LIGYSIS's existing HTML fixture retains its specific loader/receipt; the new bound
client uses the common literal HTML loader and still invokes native validation.
