# Retained disease associations in the visual explorer

The [living plan](interactive_implementation_0160.md) owns S4.4 and version
acceptance. This application increment reuses the existing native disease
association reader and original saved readers. It introduces no source,
scientific classifier, identity rule, Card schema or provider dependency.

## Visible scope and original statements

The association topic shows the native captured match/context/exclusion counts,
input-occurrence count, current selected-row count and native outcome. The first
eight context Cards have bounded original identifiers/natures and stored/matched
counts. Complete input/request states remain available through each row's native
Sources / questions route. Repeated Deck occurrences and unique captured context
Cards retain their different meanings; the application does not multiply facts
because one Card occurs twice.

Association rows expose all eleven finite native cells, including original
source/channel, identity basis, support state and row state. Ordinary previews
retain their existing eight-cell budget. Open preserves the complete original
item; Support calls the native `item.explain()` with exact page/item/revision
admission, and Sources / questions follows the exact native input/source roles.
No score is compared across sources or converted into target validity.

The current-page graph is the presentation rule
`retained_disease_association_graph@1`. Each edge projects an existing matched
statement's exact subject/predicate/object, source/channel, identity basis and
support state. Context-only rows and unknown endpoints are not edges and remain
in the original reading. Drawing the graph does not refresh sources, add a
SourceAssertion, change source direction or establish causality, efficacy or
project Evidence. Its buttons open the original rows. Names, disease hierarchy,
related xrefs and matching labels do not join identities.

## Related Cards, saving and uncertain scope

A disease → retained protein/compound → original support → exact Deck return
journey uses the existing native association links and captured context pool.
The focused Card may change while the original Deck occurrence, filter, order
and return point remain intact. Source assertions, disease equivalence and
chemical identity retain their native separate roles.

Whole-workspace saving preserves visited association selections, support views,
exact input pins and Card/Deck history through unchanged native formats. Reopening
is inert. An unvisited topic may remain `not_saved`; it is not silently recomputed
from a historical Card. To investigate a topic outside the saved scope, explicitly
open the supplied input Deck or request new source data. Missing molecular context,
empty supplied matches, source failures and exclusions are not global absence.

The first Qt receiver incorrectly assumed that an unvisited Chagas association
could be calculated after reopening an original TIM reading. The product correctly
returned `not_saved`. The corrected receiver asserts that boundary, then explicitly
opens the unchanged input Deck before the next case. No original verifier or
scientific reader is weakened. Failed receiver records remain separate.

## Deck orientation and source-produced membership

Deck rows now display a compact declared nature/identifier while retaining the
complete original pinned reference in an expandable control. Sorting/filtering,
member references, revision binding and occurrence numbers keep their native
meaning; a compact label never becomes an identity key.

Why included? shows the original membership state/scope and at most 2048 literal
JSON characters. A truncated preview points to Original membership and metadata
for the complete basis. Typed float/integer/false/null values remain in that
original text and metadata. Missing membership stays `not_stated`. A Card-ID-keyed
basis never becomes occurrence-specific support.

The public walkthrough also opens native `disease_targets@2` and
`disease_drugs@2` Decks prepared through the existing bounded API with frozen public
clients. Their complete original membership, exclusions, identity/support pins and
named derivations stay inspectable. Source association or indication membership
does not establish a validated target, an effective therapy or a clinical judgment.
Opening a retained topic/Deck does not invoke those acquisition APIs.

## Public receiving inputs and controls

`devtools/prepare_disease_walkthrough.py` prepares public MONDO TIM-deficiency and
Chagas Cards, a P60174 protein with explicitly bounded existing source enrichment,
a ChEMBL compound with source indications and the native target/drug Decks. The
mixed Deck repeats the original disease occurrence. All source responses already
belong to `temp_data/NOTICE.md`; no new scientific fixture is added.

A separate `synthetic-phenotype-control.json` uses fictitious MONDO/HPO identifiers
and the explicit source Synthetic phenotype control. It tests the display and
support of a literal disease → phenotype declaration; it asserts no scientific
relationship about a real system. Public and synthetic captures stay separate.
Native source/support unit controls and the real Qt receiver verify exact original
values, filtered scope, source roles, saved reopening, related-Card return and
byte-unchanged input files. The receiving service forbids live HTTP and records
zero source queries during navigation. Native-platform, public-installation,
workload-budget and human usefulness acceptance remain separate.

## Reconcile the bounded S4.4 criterion

The original criterion asks for disease definition/hierarchy, retained target,
drug and phenotype associations, and related Cards/Decks with exact return. It
does not require a new association classifier, unrestricted source search,
cross-source score comparison or a human usefulness verdict.

Definition/hierarchy and exact parent/source reading retain the prior
[record-query receiving](interactive_record_queries_0160.md). This increment
receives public protein associations and compound indications, actual native
target/drug Deck membership, original Support and exact related-Card/Deck return.
The separately labelled phenotype control verifies the literal presentation
branch; it does not demonstrate scientific coverage for a real disease. Original
saved scope, missing inputs, exclusions and no-match states keep native meanings.

S4.4 therefore closes at its bounded retained-information presentation scope.
S4.3/S4.5, supported mapped models, broader lifecycle/resource measurements and
actual human/version acceptance retain their separate open criteria. The
[source-bound receipt](../evidence/interactive_disease_associations_checkpoint_20261113.json)
records 196 source application cases, 195 installed runtime cases, 34 real Qt
checks each from checkout/installed wheel, 58 installed entry and 14 model
regression checks, unchanged original compatibility, artifact bytes and failed
receiver controls. No current-head full
suite, native hardware/platform qualification or public release is implied.
